# Frontend

Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, `@dnd-kit` for drag and drop. Built as a static export (`output: "export"` in `next.config.ts`, output in `out/`) which the backend serves at `/`. Sign-in and the board both go through the backend API; every board change is saved.

## Commands

```bash
npm install
npm run dev          # http://localhost:3000; proxies /api to the backend on :8000, so run the backend too
npm run build        # static export to out/
npm run lint
npm run test:unit    # Vitest + Testing Library (jsdom), src/**/*.test.{ts,tsx}
npm run test:coverage   # unit tests with coverage of src/ (report in coverage/); fails under 95% statements/lines, 90% branches/functions
npm run test:e2e     # Playwright (chromium), tests/*.spec.ts; starts its own backend (:8001, temp DB) and dev server (:3001)
npm run test:all     # unit then e2e
E2E_BASE_URL=http://localhost:8000 npx playwright test   # e2e against an already running app (backend build or Docker); starts no servers
```

## Structure

- `src/app/layout.tsx` - root layout; loads fonts (Space Grotesk as `--font-display`, Manrope as `--font-body`).
- `src/app/page.tsx` - client component: checks `/api/auth/me` on load, then renders `LoginForm` (signed out) or `Workspace` (signed in); shows "Cannot reach the server" with a Retry button if the check fails; handles logout and account deletion (back to `LoginForm`). Passes the username down; `KanbanBoard` shows "Signed in as".
- `next.config.ts` - `output: "export"`; in development only, rewrites `/api/*` to `API_URL` (default `http://127.0.0.1:8000`). Rewrites do not apply to the export, where the backend serves both.
- `src/lib/api.ts` - fetch wrappers for the backend: `getCurrentUser`, `login` (returns the registered username, which may differ in case from what was typed, or null), `logout`; the board list `listBoards`, `createBoard`, `renameBoard`, `deleteBoard` (`BoardSummary = { id, title, owner, isOwner }`), the members `listMembers`, `addMember`, `removeMember` (`BoardMembers = { owner, members }`), `listActivity` (`ActivityEntry`), `listComments`, `addComment`, `deleteComment` (`CardComment`, `mine` for your own), `addChecklistItem`, `updateChecklistItem`, `deleteChecklistItem` (return the board); and the board content routes `getBoard`, `renameColumn`, `createCard`, `updateCard`, `deleteCard`, `moveCard`, `addColumn`, `moveColumn`, `deleteColumn(boardId, columnId, moveCardsTo | null)`, whose first argument is the board id (each returns the full updated `BoardData`). All throw `RequestError` (with the HTTP `status`) if the response is not ok, except the account functions below; and `register`, `changePassword`, `deleteAccount` (return null on success or a user-facing message for known refusals such as 409/403/422, throw otherwise), and `sendChat(boardId, message, history)` for `POST /api/boards/{id}/chat` (returns `{ message, board }`, `board` null when the AI changed nothing). All calls use relative `/api` URLs.
- `src/app/globals.css` - color scheme as CSS variables (`--accent-yellow`, `--primary-blue`, `--secondary-purple`, `--navy-dark`, `--gray-text`) plus `--surface`, `--surface-strong`, `--stroke`, `--shadow`. Components use these via `var(--...)`.
- `src/lib/kanban.ts` - data model and pure logic:
  - `BoardData = { columns: Column[]; cards: Record<string, Card> }`; `Column = { id, title, cardIds }`; `Card = { id, title, details, priority, dueDate, labels, checklist }` (`ChecklistItem = { id, text, done }`) (`Priority` is `none | low | medium | high`, `dueDate` an ISO date or null); `CardFields` is a card without its id and checklist (what the card form sets). Card order lives in each column's `cardIds`.
  - Filters and summary: `CardFilter = { text, priority (or "any"), label ("" for any), overdueOnly }`, `emptyFilter`, `isFilterActive`, `matchesFilter(card, filter, today)` (text matches title, details or a label, ignoring case; label match ignores case), `boardLabels(board)` (each label once, sorted), `addDays`, `formatTimestamp(iso)` ("Mar 10, 2:05 PM", local time), `boardSummary(board, today)` (`total`, `overdue`, `dueSoon` = due today through 7 days on, `highPriority`).
  - Card field helpers: `todayISO()` (local date), `isOverdue(dueDate, today)` (string compare of ISO dates), `formatDueDate` ("Dec 24, 2026", built from parts so it never shifts a day), `parseLabels` (comma separated, trimmed, repeats dropped ignoring case), `PRIORITY_LABELS`.
  - `initialData` - sample board (5 columns, 8 cards) used as test data; the real board comes from the backend. Card 1 is high priority, overdue (2020-01-15) with labels `planning`, `q1`; card 2 is low priority due 2099-06-30.
  - `moveCard(columns, activeId, overId)` - reorder within a column or move across columns. `planMove(columns, activeId, overId)` wraps it for drag end: `{ columns, columnId, position }`, or null when nothing moves. Dropping on a column id appends; dropping on a card id inserts at that card's position.
  - `findCardPosition(columns, cardId)` - `{ columnId, position }` of a card, as the backend move route expects; used after `moveCard` to build the move request.
- `src/components/`
  - `Workspace.tsx` - signed-in view. Loads the board list, opens the remembered board (`localStorage` key `pm.lastBoard.<username>`, falling back to the first), and renders `BoardNav` above `KanbanBoard key={boardId}` (a new key gives each board fresh state, including its chat). `BoardNav` is outside `KanbanBoard` on purpose: inside, it was rendered by both the loading and the loaded branch, so an open rename form was lost when the board finished loading. Board list failures show an error in the nav.
  - `BoardNav.tsx` - `nav` named "Boards": a button per board (`aria-current="page"` on the open one; a shared board reads "<title> · <owner>", as plain text so the accessible name keeps its spaces), New board, Share, and for own boards only Rename board (one inline form, input labelled "Board name") and Delete board (`window.confirm`; disabled for the only own board).
  - `ActivityDialog.tsx` - dialog "Activity" opened from the board header: "Recent activity" list ("Deleted user" when `author` is null) with `formatTimestamp` times.
  - `CardDialog.tsx` - dialog named after the card, opened by the card's "Details for <title>" button. Checklist section (region "Checklist n/N"): a checkbox per item labelled with its text, "Remove item: <text>", "New checklist item" + Add item; the board saves these (`KanbanBoard` ticks an item at once, since the controlled checkbox would otherwise flip back until the reply, and reverts on failure). Comments: oldest first, "Delete comment: <text>" on your own, "New comment" + Add comment.
  - `ShareDialog.tsx` - dialog "Share <title>": "People with access" (owner, members); the owner adds by username ("Username to add"; 404 and 409 explained) and removes members ("Remove <name>"); a member sees "Leave board", which calls `onLeft` (the workspace drops the board and opens the first one).
  - `KanbanBoard.tsx` - client component for one board (`boardId` prop) owning its state, `DndContext` (pointer and keyboard sensors; collision detection uses `pointerWithin` and falls back to `closestCorners`, because `closestCorners` alone drops a card aimed at an empty column onto a card in a neighbouring column), and handlers for rename column, add, edit and delete card, drag end. Loads the board on mount ("Loading board..." until then, or an error with a Log out button). Each handler calls the API through `save()`, which replaces the board with the response, or restores the previous board and shows an error (`role="alert"`) if the call fails. Drag end applies `moveCard` locally first so the card does not jump back during the request. Renders the header (with Log out button, `onLogout` prop), the summary and filter bar, and the columns. Each column gets only its cards that pass the filter; its `SortableContext` lists just those, so drop positions match what is shown, while `moveCard` still works on the full card lists. The columns are laid out in a grid with one track per column (`--column-count`, at least 220px each; scrolls sideways when they do not fit).
  - `ChatSidebar.tsx` - AI chat panel (sends the latest `CHAT_HISTORY_LIMIT` = 40 turns as history; messages up to 4000 characters, matching the backend) fixed on the right, opened by the "AI Assistant" header button. Hidden (not unmounted) when closed, so the conversation survives. Keeps the conversation in state and sends the earlier turns as `history` with each message; shows "Thinking..." while waiting and disables Send; on failure shows an error and puts the unanswered message back in the input. When a reply carries a board, calls `onBoardUpdate` (the board's `setBoard`). Enter sends, Shift+Enter adds a line.
  - `LoginForm.tsx` - username/password form (the username is trimmed; on sign-in, `onLogin` gets the name as registered) with two modes: sign in, and create account ("New here? Create an account" toggles; `register()` signs in on success). Disables the button while submitting; shows an error (`role="alert"`) for bad credentials, a refused registration (message from `api.ts`) or an unreachable server.
  - `AccountDialog.tsx` - modal (`role="dialog"`, name "Account") opened by the board's Account button: "Signed in as", change password (result in `role="status"`), delete account (password required; calls `onAccountDeleted`, which returns to sign in).
  - `KanbanColumn.tsx` - droppable column (the title input is keyed on the title and `failedSaves`, a count `KanbanBoard` raises on every failed save, so a rejected rename shows the saved title again); header count is "N cards", or "n of N cards" while a filter hides some; an empty result says "No matching cards" instead of "Drop a card here"; under the title, Move column left / right (disabled at the ends) and Delete column (disabled for the only column; opens `DeleteColumnPanel`); title is an uncontrolled inline input saved on blur or Enter (blank reverts; `key={column.title}` resets it when the saved title changes); renders cards in a `SortableContext` and `NewCardForm`.
  - `KanbanCard.tsx` - sortable card. Mouse/touch: drag from anywhere on the card (pointer listeners on the card). Keyboard: a grip handle button (`aria-label="Drag <title>"`) carries the sortable attributes and the keyboard listener, so the card itself is not a `role="button"` around the Edit and Remove buttons, and Space/Enter on those buttons still click them. The card buttons are Edit, Details and Remove. Focus the handle, Space to pick up, arrow keys to move, Space to drop. Edit switches to `CardForm` ("Save") and disables dragging.
  - `KanbanCardPreview.tsx` - card rendered in the `DragOverlay` while dragging.
  - `BoardSummary.tsx` - `dl` "Board summary" with tiles Cards, Overdue (purple when above 0), Due in 7 days, High priority.
  - `FilterBar.tsx` - `role="search"` "Filter cards": "Search cards", "Filter by priority", "Filter by label" (the board's labels), "Overdue only"; while a filter is set, "Showing N of M cards" (`role="status"`) and Clear filters. Filter state lives in `KanbanBoard` (reset when switching boards).
  - `AddColumnForm.tsx` - "Add column" button in the header's column chip row that opens an inline name input ("New column name").
  - `DeleteColumnPanel.tsx` - inside a column being deleted: for a column with cards, a select "What happens to the cards" ("Move to <column>" for each other column, default the first, or "Delete the cards"); for an empty one, a plain question.
  - `CardForm.tsx` - the card form for adding and editing: title (required), details, priority select, due date (`type="date"`, empty means none), labels (comma separated). `emptyCard` is the blank starting value.
  - `CardMeta.tsx` - priority badge, due date ("Due ..." or "Overdue: ..."), checklist progress ("Checklist n/N") and label chips under a card; renders nothing when none are set. Used by `KanbanCard` and `KanbanCardPreview`.
  - `NewCardForm.tsx` - "Add a card" button that opens `CardForm`.

## Tests

- Vitest runs with `mockReset: true`, so set mock return values in each test.
- `src/components/KanbanBoard.drag.test.tsx` - jsdom cannot run a real dnd-kit drag (every element measures 0x0), so `@dnd-kit/core`'s `DndContext` and `DragOverlay` are replaced by stand-ins that keep the board's handlers; covers the overlay, the immediate move and its request, the rollback on failure, and drops that change nothing.
- `src/lib/kanban.test.ts` - `moveCard` reorder, cross-column move, drop on column, unknown ids, drop on itself; `findCardPosition`; `todayISO`, `isOverdue`, `formatDueDate`, `parseLabels`; `matchesFilter` (each field and combined), `boardLabels`, `addDays`, `boardSummary`.
- `src/lib/api.test.ts` - each board function calls its route with the right method and body (`fetch` stubbed); errors throw.
- `src/components/Workspace.test.tsx` - API mocked: opens the first or remembered board (and ignores a stale one), switches, creates, renames, deletes, failures, and the switcher staying usable when a board fails to load.
- `src/components/FilterBar.test.tsx`, `BoardSummary.test.tsx` - each filter control, count and Clear only while filtering, label options; tile values.
- `src/components/AddColumnForm.test.tsx`, `DeleteColumnPanel.test.tsx` - adding (trimmed, blank ignored, cancel); deleting with the default target, a chosen target, deleting the cards, an empty column, cancel.
- `src/components/CardForm.test.tsx` - all fields submitted trimmed and parsed, editing and clearing values, blank title, cancel.
- `src/components/CardMeta.test.tsx` - nothing for a plain card, priority, due date and labels, overdue.
- `src/components/BoardNav.test.tsx` - listing and current board, select, create (blank refused), rename prefilled, cancel, delete with and without confirmation, only board, error; shared boards (owner shown, owner-only actions hidden, not counted as own).
- `src/components/ActivityDialog.test.tsx`, `CardDialog.test.tsx` - checklist items, progress, toggle, remove, add (blank ignored); comment listing (deleted authors, own comments deletable), empty states, add, blank ignored, delete, failures.
- `src/components/ShareDialog.test.tsx` - listing, add (404/409/other explained, blank ignored), remove, member leave, failures, close (`RequestError` kept real in the mock).
- `src/components/ChatSidebar.test.tsx` - `sendChat` mocked: send and reply, history, Enter, loading state, error, board update passed on or not, blank message.
- `src/components/KanbanBoard.test.tsx` - with `fetch` stubbed (`respond(board)` queues a response): load, loading state, load error, rename column (blank reverts without a request), add, delete and edit card, blank title and blank edit send nothing, cancel edit, failed save shows an error and keeps the board, card counts, drag handle, logout callback, a chat reply with a board updates the board, card fields shown and sent, add / move / delete column requests, summary values, filtering by text (with "n of N cards" and "No matching cards"), label, priority and overdue. Drag moves are covered by e2e.
- `src/components/LoginForm.test.tsx` - successful login, invalid credentials, unreachable server, disabled while submitting; registering, refused registration, switching modes (`@/lib/api` mocked).
- `src/components/AccountDialog.test.tsx` - signed-in name and close, change password (success, refused, failed request), delete account (success, wrong password).
- `src/app/page.test.tsx` - login form when signed out, unreachable server, board when signed in, login then board, logout then login form (`@/lib/api` mocked, including `getBoard`). Wait for the board heading before clicking Log out: the loading state has its own Log out button that the loaded board replaces.
- `tests/kanban.spec.ts` - e2e on the demo user's first board (signs in first via `tests/helpers.ts`; a new browser context has no remembered board): board loads; add, delete, edit card, rename column, drag between columns and within a column (by the card body), each checked again after a reload; keyboard move; Space on Edit opens the editor. The board is shared server state (and the user's real board when run against the container), so each test creates uniquely titled cards (`uniqueTitle`), removes them at the end, and restores a renamed column. Ids are random, so columns are found by position and cards by title (or by `data-testid` once found, since a card in edit mode has no title text). Mouse drags must stay inside the viewport (a real board can be taller than it): scroll the card into view and drag sideways at its height (columns in a row share its height). Wait for the `/move` response before reloading after a drag, since moves are applied before the request finishes. Run repeats with `--workers 1` (`--repeat-each` runs copies of a test in parallel on the same board). An arrow key pressed right after pickup is sometimes ignored while dnd-kit measures drop targets, so the keyboard test presses again (`toPass`) until the announcement shows a new target. Keyboard drags must wait for dnd-kit's live region (`[id^="DndLiveRegion"]`) to announce each step (pickup, new target) before pressing the next key; otherwise keys can be lost.
- `tests/chat.spec.ts` - e2e with `/api/chat` mocked (`page.route`) to return the real board plus a card: the card appears in Done without a reload. Nothing is saved, so nothing to clean up.
- `tests/filters.spec.ts` - e2e on a board of its own: search and label filters, dragging a card while others are hidden, clear, reload.
- `tests/comments.spec.ts` - e2e on boards of their own: comment, reload, delete, activity shows the comment and the card; a checklist (add, tick, progress after reload, remove). `getByLabel` also matches by substring, so the item checkboxes need `exact: true` next to the "Remove item: ..." buttons.
- `tests/sharing.spec.ts` - e2e with two browser contexts (two registered users): share, member sees the board with its owner and no owner actions, adds a card the owner sees, leaves; both accounts deleted. Note role-name matching is a case-insensitive substring by default, so use `exact: true` for short names like "Share".
- `tests/columns.spec.ts` - e2e on a board of its own: add a column, move it left, delete Backlog moving its card into it, reload; deletes the board.
- `tests/boards.spec.ts` - e2e: create a board (empty), add a card there, reload reopens it, switch back (card not on the first board), rename, delete (dialog accepted). Removes its board.
- `tests/accounts.spec.ts` - e2e: register a unique user (`e2e_<timestamp>`), log out and in, change password (old one refused), delete the account (so nothing is left behind); a taken username is refused.
- `tests/auth.spec.ts` - e2e: login required, wrong password error, session survives reload, logout survives reload.
- Tests that change a board should use their own (`createBoard` / `deleteOpenBoard` in `tests/helpers.ts`): test files run in parallel workers, and those on the demo board see each other's cards. `createBoard` waits until the new board is open; before that, the previous board is still on screen and would get the changes.
- dnd-kit swallows clicks for 50 ms after a pointer drop (a capturing document listener, so a drop is not also a click); a test that clicks right after a fast `/move` response must retry the click (see `filters.spec.ts`).
- The chat sidebar is hidden with Tailwind's `hidden` class, which jsdom does not apply, so its Close button counts as visible in unit tests; scope queries to the dialog in question.
- Next.js renders its own empty `role="alert"` route announcer, so filter `getByRole("alert")` by text in e2e tests.

## Test hooks

- Columns: `data-testid="column-<columnId>"`; cards: `data-testid="card-<cardId>"`.
- Column title input: `aria-label="Column title"`; column buttons: "Move column <title> left", "Move column <title> right", "Delete column <title>" (kept distinct from card buttons); card buttons: `aria-label="Drag <card title>"`, `aria-label="Edit <card title>"`, `aria-label="Delete <card title>"`; card form inputs (add and edit): `aria-label` "Card title", "Card details", "Priority", "Due date", "Labels" (placeholders "Card title", "Details").
